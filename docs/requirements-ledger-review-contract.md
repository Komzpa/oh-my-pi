# Requirement ledger completion contracts

- A mapping failure must reject receipts even when saved TODO timestamps match. The saved-row-history fallback applies only when artifact resolution succeeded.
- Markdown receipts require id, verdict, evidence, and artifact columns. An omitted raw words column binds to the immutable parent ask from the matching audit assignment snapshot. If present, every row (including split sub-IDs) must echo that complete ask; partial, empty, duplicate, or reworded echoes cannot authenticate a pass.
- Reloading a background auditor assignment must preserve its exact assigned TODO rows. A receipt for another row cannot be accepted.
- Error and abort finalization must suppress unverified retained narrative when requirements remain open, preserving provider stop/error metadata. Quieted user notices and tool calls must not expose failed narrative.
- A later user restatement explicitly naming the missing-image requirement can be associated by classifying the blocked requirement as merged into that new candidate. Both raw asks remain in audit inputs; rows transfer and old verdicts are discarded. A fresh audit is required. Unrelated or older candidates cannot resolve a blocked linked image requirement.
- Filesystem and path Node APIs use namespace imports as required by AGENTS.md.
- Gate artifact display replaces the home directory with `~` through the centralized shortenPath helper.
- Normal final text remains byte-for-byte the assistant's own text plus at most one short audit-status line. Gate details use the existing hidden next-turn custom-message queue, never user-visible answer text.
- Model gate notices have one short entry per requirement, shared rejection/checkouts stated once, one grouped next action, no raw user quotes or worker results, and a 1,500-byte UTF-8 cap with `+N more` for omitted requirements. An unchanged open set and reasons must not queue another notice.
- Explicit row resources already take precedence over persisted checkout/owner fallbacks. A saved receipt rejection naming a different checkout or HEAD must not be repeated as a current row failure; missing current-artifact QA still blocks completion.
- Explicit string yield data is recorded verbatim as task receipt text; object and array data remains JSON. JSON-encoded Markdown receipt strings from older producers remain readable. Missing verdict, evidence, or artifact columns and foreign requirement IDs still fail validation.
- Auditor task arguments MUST carry each referenced image by reference (`type`, `mimeType`, `sha256`, `rn`, `index`, plus `artifactPath` and/or `sourcePath` when known) and MUST NOT include image bytes. The runtime MUST retain SHA-addressed `requirement-image-<sha256>` artifacts when source files are unavailable; child delivery MUST verify resolved image bytes against the reference SHA-256 and represent missing or mismatched bytes as unavailable text, not as an image or task failure. Five 400 KiB images MUST produce serialized task arguments under 20,000 characters, with no repeated byte payloads for repeated SHA values. When no images are referenced, image transport MUST NOT alter task arguments beyond the existing QA AUDIT INPUT enrichment.
