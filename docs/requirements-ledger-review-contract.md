# Requirement ledger completion contracts

- Legacy untyped receipts MUST reject an owner-mapping failure even when saved TODO timestamps match; saved-row-history fallback applies only after artifact resolution succeeds. Typed receipts MUST resolve by receipt kind before owner mapping, so unavailable owner mappings do not make them stale.
- Auditor output MUST use the supplied canonical header with id, source sha256, verdict, evidence, and artifact identity. Copy the full SHA-256 of the captured raw words, never multi-line owner prose, into the source column; intake MUST verify it against the authenticated immutable assignment and persist that assignment's exact source words. The first lane/task brief remains one stored requirement referenced by ID and digest. Existing receipts without a source digest still bind to the authenticated source; a supplied missing/wrong digest, foreign ID, changed source snapshot, or foreign/stale artifact MUST reject. Authenticated R18a/R18b clause rows fold to R18 with all evidence retained: any fail wins, otherwise any unverifiable wins, otherwise pass; every clause MUST name the same artifact. Duplicate IDs, mixed parent/clause rows, unauthenticated suffix IDs, or differing artifacts MUST refuse. DONE retries MUST request exactly one audit per affected TODO row with only its exact linked parent IDs and current typed identity (Git commit with optional exact paths, file SHA-256, bounded manifest SHA-256, or HTTP/service deployment declaration). Never substitute another row's IDs or identity.
   - Reloading a background auditor assignment must preserve its exact assigned TODO rows. A receipt for another row cannot be accepted; the diagnostic MUST name the assigned rows and the named rows, and MUST be issued before artifact identity checks. Artifact cells MUST use exact whole row labels (bare `Row @ sha` or quoted `row "Row" @ sha`, `TODO row "Row" @ sha`, with `\"`/`\\` escapes); substring matching MUST NOT bind a row, and an unlabelled legacy cell MUST project only onto an assigned row. A label naming a linked but unassigned row MUST reject the receipt even beside an assigned row label; unrelated `x @ y` evidence beside an assigned row label remains evidence.
   - Audit dispatch scope MUST come from structured `task.requirementIds` or exact `task.name` matching the canonical TODO row's structured `schedule.owner`. IDs, row names, examples, quotations, and shared context in free text MUST NOT select rows. Workers without either explicit IDs or a matched owner MUST create no requirement assignment. Session hydration and subsequent TODO mutations MUST preserve schedule ownership and artifact bindings. Oracle: `AuditR23MergeRow` owns `Merge open PRs #44 #45 #57 into PR #60 branch`; a free-text audit with that name MUST persist the R23 assignment and allow completion after a fresh pass, while unrelated R6 prose cannot enroll R6.
- Error and aborted turns MUST bypass requirement publication decoration entirely: preserve their actual text and provider stop/error metadata. Normal final answers MUST retain all original text and append at most one audit-status line beneath it, never replace the answer. Oracle: final text with open requirements remains visible beside its status; `stopReason="error"` preserves provider error text without any audit-status replacement.
- A later user restatement explicitly naming the missing-image requirement can be associated by classifying the blocked requirement as merged into that new candidate. Both raw asks remain in audit inputs; rows transfer and old verdicts are discarded. A fresh audit is required. Unrelated or older candidates cannot resolve a blocked linked image requirement.
- An acknowledgement or emotional reaction with no deliverable (including repeated `го го го`, pure emoji, and object-free swearing) MUST be recorded at intake as `not-a-requirement` with its original words and a reason, never as a blocking candidate. A standalone absolute Markdown reference whose basename starts `steer_` is a lead control message, not a separate product requirement; its instructions still apply. Unknown or obligation-bearing words, ordinary user-authored file asks, and images MUST remain eligible for classification; slash commands remain unaffected.
- A missing/self/unknown/inactive merge-target diagnostic MUST recover with linked-target availability only: with no linked target it MUST offer source linking or not-a-requirement with row creation and MUST NOT name a merged/mergeInto directive; with linked targets it MUST list their IDs as `Available active merge targets: ["Rn"]` beside a non-executable merged placeholder and MUST NOT select a target. Actual candidate merge acceptance and image restatement are unchanged.
- Filesystem and path Node APIs use namespace imports as required by AGENTS.md.
- Gate artifact display replaces the home directory with `~` through the centralized shortenPath helper.
- Normal final text remains byte-for-byte the assistant's own text plus at most one short audit-status line. Gate details use the existing hidden next-turn custom-message queue, never user-visible answer text.
- Model gate notices have one short entry per requirement, shared rejection/checkouts stated once, one grouped next action, no raw user quotes or worker results, and a 1,500-byte UTF-8 cap with `+N more` for omitted requirements. An unchanged open set and reasons must not queue another notice.
- Explicit row resources already take precedence over persisted checkout/owner fallbacks. A saved receipt rejection naming a different checkout or HEAD must not be repeated as a current row failure; missing current-artifact QA still blocks completion.
- Explicit string yield data is recorded verbatim as task receipt text; object and array data remains JSON. JSON-encoded Markdown receipt strings from older producers remain readable. Missing verdict, evidence, or artifact columns and foreign requirement IDs still fail validation.
- Auditor task arguments MUST carry each referenced image by reference (`type`, `mimeType`, `sha256`, `rn`, `index`, plus `artifactPath` and/or `sourcePath` when known) and MUST NOT include image bytes. The runtime MUST retain SHA-addressed `requirement-image-<sha256>` artifacts when source files are unavailable; child delivery MUST verify resolved image bytes against the reference SHA-256 and represent missing or mismatched bytes as unavailable text, not as an image or task failure. Five 400 KiB images MUST produce serialized task arguments under 20,000 characters, with no repeated byte payloads for repeated SHA values. When no images are referenced, image transport MUST NOT alter task arguments beyond the existing QA AUDIT INPUT enrichment.
- Freshness checks MUST return the exact failing reason (`getRequirementVerdictStaleness`, null when fresh) and name the expected identity. Requirement source identity MUST come from the authenticated assignment snapshot before artifact identity; the auditor omitting an image tag prefix or varying prose MUST NOT invalidate that source binding. A receipt bound to a Git commit, file/manifest hash, or deployment version MUST remain fresh when only its row's schedule, estimate, or evidence changes; receipt time versus a metadata edit is not an artifact change. A changed whole-checkout Git commit MUST block a whole-SHA receipt; a path-scoped Git receipt remains fresh while every named blob OID and mode is unchanged. An absent linked row MUST resolve its latest unambiguous canonical historical artifact declaration regardless of TODO status, including pending, in_progress, and abandoned; a current row MUST take precedence and duplicate historical rows MUST remain unresolved. Lookup MUST NOT change row status, restore an archived row, relink a requirement, widen receipt paths, or grant a QA pass; dirty or missing artifacts and stale or missing QA evidence MUST retain their existing refusals. Saved-row-history freshness applies only when no artifact identity is available; canonical raw-source and declared-target changes still invalidate the affected receipt.
- Legacy untyped dirty-Git receipts MUST match exact HEAD and a content fingerprint over HEAD plus sorted dirty paths' status and bytes (symlink targets, deletions, rename origins); status-only fingerprints are unsound. HEAD, status, and every participating path MUST remain stable through fingerprinting; drift or fingerprint failure is unverifiable. Exclude `dirty-fingerprint=` from commit-SHA matching. Typed Git receipts are `git:<absolute-root>@<full-commit>` with OPTIONAL `paths=[<exact-repo-relative-paths>]`: an explicit `paths=` receipt binds only the named paths' immutable Git blob OIDs and modes (unrelated dirt and HEAD movement do not matter when those identities are unchanged; changed named identity is stale); a receipt without paths binds the whole checkout (exact HEAD and a clean tree: a new HEAD is stale, a dirty unscoped checkout is unverifiable). Missing/ambiguous named scope is unverifiable.
- Typed Git identity is `git:<absolute-root>@<full-commit>` with OPTIONAL `paths=[<exact-repo-relative-paths>]`; preserve the exact absolute root. Without paths the receipt binds the whole checkout: exact HEAD and a clean tree (new HEAD stale; dirty unscoped unverifiable). With explicit paths compare only every declared path's immutable Git blob OID and mode, independent of HEAD movement or unrelated dirt. Typed file identity MUST be `file:<absolute-path>@sha256=<sha256>`; preserve the exact absolute path, including trailing whitespace, without trimming or substituting a neighboring path. A directory or multi-file resource uses a bounded manifest SHA-256 rooted at the directory or common parent, covering every declared target exactly once in stable order; reordering preserves identity, changed resource sets require reasoned relink. Capture row-declared typed identities in the dispatch snapshot and compare them before dispatch and after async completion; metadata-only owner, notes, and status changes do not alter identity. Symlinks, special files, bound overruns, races, missing named targets, or missing/ambiguous Git path scope are unverifiable, not stale. A changed named identity is stale.
- The canonical file identity formatter and parser MUST use the same literal `@sha256=` wire label with a full 64-hex digest; unlabeled digests, malformed or short hashes, and file attributes MUST be rejected. Captured file identities MUST round-trip through the formatter, dispatch input, and actual receipt intake without losing that label.
- Legacy untyped assignments retain worker-cwd ownership: every finished non-isolated assigned worker (not QA-only) MUST have its actual effective cwd bound on its assigned TODO row BEFORE execution and preserved after registry cleanup through sync/async/wait; the binding is NEVER a QA pass, and an isolated worker with no binding MUST NEVER borrow main cwd. A receipt citing only dispatch-time HEAD after the row's artifact identity advances is stale at intake and MUST NOT authorize completion; schedule, estimate, or evidence edits alone are not artifact advancement. These owner-cwd, dirty-fingerprint, and identity-free saved-row-history rules apply only to legacy untyped receipts; typed receipts resolve their declared artifact identity independently.
- The main session owns its cwd checkout by default for owner `Main`/`main` or an ownerless row, even with an empty resource list. Explicit resource paths and valid persisted artifact bindings MUST retain precedence. A clean session checkout at audited HEAD H MUST permit native `done` for its Main-owned row; an unmapped non-main worker MUST NOT borrow that checkout and MUST remain unverifiable. Archived rows still require their persisted binding.
- Initial classification of a candidate MUST atomically link the exact existing rows and supplied artifact binding, including replacement of provisional row resources or deployment; an unnecessary relink flag MUST NOT route this first classification into a linked-only amendment or require a relink reason. `classify` with `relink: true` on an already-linked requirement MUST require a reason, persist an amendment with old rows, new rows, and reason, clear receipts of changed rows only, and keep untouched row receipts and the original raw source. Changing a shared row binding during first classification MUST invalidate every affected requirement's receipt, just as a linked cutover does. Oracle: a candidate plus an existing resource-bound row accepts a changed resource binding with or without relink; an already-linked requirement still refuses a changed binding without a reason. A per-row receipt is scoped to its own row; legacy all-row receipts carry over only when they resolve to that row.
- An ordinary classified requirement MUST remain immutable unless `classify` cites `supersededBy="<newer owner Rn>"` and a nonblank reason. The cited canonical owner statement MUST be strictly newer than the original requirement and any owner statement already used to supersede it; missing, self, unknown, equal/older, or reused authority MUST refuse without writing. An accepted transition MUST append an amendment recording old/new classifications, old/new rows, the superseding ID, timestamp, and reason, preserve the original raw source and earlier ledger snapshots, invalidate affected receipts, and stop cancelled requirements from blocking completion/publication. Same-class reasoned relink and the existing missing-image restatement path retain their own contracts. Oracle: linked R5 plus later R14 cancelling fold rows accepts R5 → not-a-requirement citing R14; no newer owner statement refuses.
- Native `rm` and plan-replacing `init` MUST allow requirement-linked completed rows to leave the active plan only after the shared completion gate rechecks every linked requirement against the current artifact. Persisted canonical row snapshots MUST retain their completed status and artifact bindings for later freshness checks. Unfinished rows and stale or missing QA evidence MUST block removal; the recovery MUST offer completion or reasoned relink, never an impossible linked-to-not-a-requirement classification.
- After any asynchronous artifact gate, native TODO mutation MUST compare the current plan with its pre-gate snapshot before applying changes. A concurrent row, status, schedule, or artifact-binding edit MUST cause a retry refusal and remain intact; no stale snapshot may overwrite it.
   - Malformed verdict tables MUST diagnose each invalid parent verdict qualifier separately with the verbatim cell plus the allowed words pass|fail|unverifiable; valid sibling parents MUST still be accepted, and prompt caveats/qualifiers belong in evidence.
- When an assistant batch holds explicit todo mutations, sibling non-todo calls MUST run their `beforeToolCall` gate only after those mutations settle, so the gate reads post-mutation state; a failed classify MUST NOT bypass the gate. Deferred siblings MUST NOT be speculatively admitted before their gate settles, and execution MUST receive any hook-revised arguments rather than a pre-gate cached snapshot.
- Unclassified candidates MUST remind new task spawns without blocking dispatch. They still block TODO completion/closure and leave the candidate intact. Ordinary bash/read/write and worker controls remain allowed; a pure task abort/cancel call receives no classification reminder. Oracle: with an unclassified candidate, new task dispatch receives its reminder, agent stop/broadcast and proc kill remain admitted, and TODO done remains blocked.
- `outputSchema: false` in task/eval calls, agent output declarations, or inherited task schemas MUST explicitly disable the output wrapper, including strict mode, and MUST prevent inheriting an agent's schema again. A raw auditor table MUST pass through verbatim without a schema-rejection payload; malformed non-boolean schemas remain rejected.
- An unclassified-candidate gate refusal MUST NOT present open TODO rows as a runnable `rows=[...]` classify selection. The `rows` parameter carries available rows only: the suggested classify call keeps the non-executable `rows=["<exact todo row>"]` placeholder with the exact requirement ID and raw text, names the originating ask/tool call as the only confident selector when present, and appends the available rows once as a separate list. Oracle: an R17 card-image complaint and an R18 `Answer to toolu_...` X-ray answer with only `Rebuild PR #54 from Maksim's whole branch` open MUST NOT contain that row in `rows=[...]`; completion remains blocked until classification; task dispatch carries a reminder.
- Typed deployment bindings replace binary scanning and live-probe witnesses. HTTP deployments use `deploy:<HTTP(S)-URL>@<version>` with a required `field=<dot.path>`; authorize its exact URL through the operator-owned `OMP_TRUSTED_DEPLOYMENT_URLS` JSON string array before making any request, then probe without credentials, redirects, or response bodies over 64 KiB, with a 5-second timeout, and compare the field's observed value to the declared version. Service deployments use `deploy:<literal.service>@<version> scope=<user|system> env=<ENV_KEY>`; inspect the actual running service process's environment (never configuration files) and compare that key's value to the declared version. A service mismatch MUST report only a generic mismatch; never export the observed environment value into diagnostics or the auditor identity. A missing service/process, inaccessible probe, missing field/key, or unavailable value is unverifiable; a changed named version is stale. Probe on every close/publication. Resolve typed deployment identity before owner mapping; do not fall back to cwd or Git. The authenticated receipt MUST name the exact declared deployment and report the observed version and probe evidence; absent probe evidence is unverifiable. The opaque artifact cell remains evidence, not a TODO row title; exact row-label rules in clause 26 still apply.
- Row labels bind by whole-label equality against the known row set only: quoted `row "Row" @ …`, optionally prefixed with `TODO` or `R<n>`, is always explicit, while bare `X @ …` names a row only when `X` is a known row and is otherwise opaque evidence. Row scoping and typed identity parsing MUST share the same quoted-prefix grammar. After removing that prefix, Git path coverage, file hashes, and deployment probes MUST remain typed; malformed typed identities MUST be rejected, never downgraded to legacy SHA receipts. An unlabelled legacy cell projects only onto members of the row set.
- Receipt tables map by header, never by position: extra `|` cells from an unescaped pipe fold into evidence only, or reject only the named row with an `unescaped | in evidence` reason while unaffected rows are still accepted. The QA prompt escapes a literal `|` as `\|` in cells.
- Test harnesses MUST remove inherited `OMP_LANE_UNIT` from each test child environment, not set it to an empty string: the production single-writer bypass MUST NOT disable chief-gate verification. Oracle: a runner spawned with `OMP_LANE_UNIT=qa-owner-strand` produces a child with lane mode disabled while preserving an unrelated control variable, and the previously bypassed chief-gate tests pass.
- Production-data rows MUST bind an authenticated verdict to the declared artifact kind: Git checkout/commit, file/SHA-256, or an external-state readback receipt file containing its source and observation time. A missing checkout MUST NOT reject a file receipt. A fresh readback-file pass MUST permit native `done`; changing that file after the audit MUST refuse as stale with the expected and observed hashes. A file hash mentioned only in evidence MUST NOT silently replace a Git identity in the artifact cell.
- The authenticated auditor owns semantic measurement verdicts. Receipt intake MUST preserve its explicit pass, fail, or unverifiable verdict without deriving a second verdict from free-text claimed/measured columns, digit-token equality, inferred bounds, units, rounding, or citation numbers. Claimed and measured text MUST remain in persisted evidence. Identity, assignment, schema, and current-artifact freshness checks remain mandatory; a current-artifact auditor fail MUST still prevent completion. Oracle: the original R30 rounded 64.57 MB/≈14× receipt with measured 64.571309 MB/14.0000000596× remains pass; the same receipt explicitly marked fail remains fail.
- An explicit quoted row's legacy `@ <full Git commit>` MUST bind that row's checkout identity; installed-binary SHA-256 values or other hashes in trailing evidence MUST NOT become competing Git commits. Unlabelled ambiguous hashes, changed commits, dirty checkouts, foreign row labels, and malformed typed identities remain refused. Oracle: the original corrected R63 receipt naming d944615c plus binary SHA-256 735156d2 reaches authenticated intake and native done, replacing its old aab928bb fail; the same current-artifact receipt marked fail still blocks done.

### Git status freshness

Session Git status readers share one probe per worktree every ten seconds. Index,
HEAD, symbolic ref and packed-ref metadata changes, native Git mutations and
session tool writes invalidate snapshots without resetting the probe interval.
Unscoped Git receipt checks compare the metadata and write generation around the
status read; a reused snapshot is not an independent second scan. External
unstaged edits can remain unseen until the ten-second snapshot expires. Named
path receipts continue to verify their declared files directly.
