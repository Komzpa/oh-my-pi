# todo requirement ledger

The requirement ledger extends the [todo tool](todo.md) with classification, authenticated audit receipts, and user-owned pending checks.

## Source

- Tool: `packages/coding-agent/src/tools/todo.ts`
- Runtime gates: `packages/coding-agent/src/session/requirements-ledger-runtime.ts`
- Ledger: `packages/coding-agent/src/tools/requirements-ledger.ts`
- Model-facing requirement supplement: `packages/coding-agent/src/prompts/tools/todo-requirements.md`, appended to the shared `packages/coding-agent/src/prompts/tools/todo.md` description.

## Same-turn requirement classification

Every new main-session user message that creates an unclassified requirement candidate gates mutating tool calls in that same turn; the `todo` tool remains available to classify it. Bare approval replies are exempt: a message that is only `go`, `ok`, `да`, or `продолжай` (whitespace-normalized) with no images is ignored, creating no requirement or gate and allocating no requirement ID.

An already-classified requirement can change only when the owner has supplied a newer canonical requirement statement. Use `op="classify", id="R5", classification="not-a-requirement", supersededBy="R14", reason="R14 cancels the fold rows"`. The superseding statement must be strictly newer than R5 and the last owner statement used to supersede it; missing, self, unknown, equal/older, reused IDs and blank reasons refuse without writing. The transition appends history with old/new classifications and rows, reason, timestamp, and superseding ID; original words and earlier snapshots remain intact. Cancelled requirements no longer gate completion or publication; reactivation requires newer owner authority and fresh QA. Ordinary same-class `relink=true` keeps its existing reasoned row-change contract.

## Requirement completion gate

Native `todo done`, `/todo done`, and assistant publication share `evaluateRequirementDoneGate` in `requirements-ledger.ts`. Every row needs a fresh authenticated `qa-auditor` pass for each requirement linked to that row; receipts are saved per row with receive time. Legacy all-row receipts remain readable only for their corresponding artifacts.

Receipts MUST use exact assigned parent IDs, never letter suffixes. Raw words are optional context; authenticated assignment snapshots bind canonical source words. Authenticated clause sub-rows fold to their assigned parent only when all artifacts match: any fail wins, otherwise unverifiable wins, otherwise pass. Keep every clause’s evidence. DONE refusals MUST request exactly one audit per affected TODO row, grouping that row's exact linked parent IDs and current typed identity: `git:<absolute-root>@<full-commit>` with OPTIONAL `paths=[<exact-repo-relative-paths>]` (no paths binds the whole checkout: exact HEAD and a clean tree; explicit paths bind only those paths' blob OIDs and modes), `file:<absolute-path>@sha256=<file-or-manifest-sha256>`; `deploy:<HTTP(S)-URL>@<version> field=<dot.path>`; or `deploy:<literal.service>@<version> scope=<user|system> env=<ENV_KEY>`. Never substitute another row's IDs or identity.

Audit reloads preserve exact assigned TODO rows. Reject another row before identity checks and name assigned and receipt-named rows. Labels bind by whole-row equality: quoted `row "Row" @ ...` is explicit; bare `Row @ ...` names a row only when `Row` is known; otherwise the cell is opaque evidence. An unlabelled legacy cell projects only onto assigned rows, and multi-row cells are split by exact labels. Decode Markdown `<br>` in raw words as newlines. Split table cells only on unescaped `|`; locate columns by header name, accepting extra columns and the `artifact identity` spelling. Missing, duplicate, malformed, mixed parent/sub-row forms, mismatched clause artifacts, malformed requested verdicts, and missing required requested receipt fields MUST fail. Authenticated suffix rows bind only their assigned canonical parent; changed assignment snapshots remain rejected. Distinct unrelated parent IDs MUST be ignored before their fields are validated and MUST NOT poison the requested verdict; additional records require that same assigned TODO row.

Resolve typed identity by receipt kind before owner mapping; an unavailable owner mapping does not make a typed receipt stale. Typed Git with explicit `paths=` compares only declared path blob OIDs and modes: unrelated dirt and HEAD movement do not matter; a whole-checkout Git receipt without paths requires the exact HEAD and a clean tree (a new HEAD is stale, a dirty unscoped checkout is unverifiable); a changed named identity is stale with expected and observed values, and missing/ambiguous path scope is unverifiable. Typed files retain the exact absolute path, including trailing whitespace. Manifests are bounded, deterministic, order-independent, and cover every declared target exactly once; resource-set changes require reasoned relink. Capture each row's immutable source/ask and declared typed identity in the dispatch snapshot and compare both before dispatch and after async completion; owner, notes, and status changes do not alter identity. A receipt bound to a Git commit, file/manifest hash, or deployment version MUST remain fresh when only its row's schedule, estimate, or evidence changes.

Typed declarations take precedence over owner/session cwd. An authenticated bare full Git commit with the exact assigned row label MAY bind to that row's sole unscoped declared Git root; normalize through the existing typed coverage and whole-checkout probe while retaining the original receipt. The checkout MUST be clean at that exact current HEAD. Ambiguous commits or targets, foreign rows, path-scoped targets, file targets, and deployment targets MUST NOT use this Git interoperability path. Only successful probe proof bound to the exact original artifact authenticates freshness; saved-row history MUST NOT substitute for it. Other legacy untyped receipts retain their prior resolution, saved-row-history, and worker-cwd ownership rules: bind each non-isolated worker's actual effective cwd to its assigned rows before execution and preserve it after registry cleanup. That binding is never a QA pass; an isolated worker never borrows main cwd. Legacy dirty Git still requires exact HEAD plus its full content fingerprint. These legacy fallbacks MUST NOT change typed resolution.

A claimed figure with a comparison (`>=`, `<=`, `>`, `<`, `≥`, `≤`, `at least`, `at most`) and its measured figure MUST compare numerically in their comparable stated units, with an omitted measured unit inheriting the claimed metric: inclusive bounds are satisfied at equality, strict bounds are not, and only a genuine numeric miss downgrades `pass`. Freshness refusals name the failing check and expected identity. Authenticate the assignment’s immutable source snapshot before artifact identity; prose changes or missing image tags in the optional raw-words context do not change that source identity. A file uses exact-path SHA-256. A non-Git directory or multiple files use SHA-256 of `["omp-requirement-manifest/v1", [[relPath, fileSha256], …]]` in codepoint order, rooted at the directory or files' common parent, bounded to 4096 files, 256 MiB, and depth 32. Top-level file/directory paths are canonicalized before the existing non-following stable reads. If the given path differs, its identity also carries `canonical=<absolute-path>` (JSON-quoted when needed); a changed canonical destination is stale even if the bytes match. Directory symlinks are not followed: each contributes a typed symlink row containing a SHA-256 of its `readlink` target string. Retargeting changes the manifest; editing target bytes does not. Dangling or cyclic links inside a directory are valid entries, while a dangling top-level path, special files, bound overruns, and races remain unverifiable with the failing path and reason.

When a merge target is missing, self, unknown, or inactive, the diagnostic lists only available linked targets as `Available active merge targets: ["Rn"]` beside a non-executable merged placeholder without choosing one; with no linked target it offers source linking or not-a-requirement with row creation instead.

### Typed deployment probes

HTTP deployments use `deploy:<HTTP(S)-URL>@<version>` plus `field=<dot.path>`. Probe the URL without credentials or redirects, with a 5-second timeout and a 64 KiB response cap; compare that field's observed value to the declared version. Service deployments use `deploy:<literal.service>@<version> scope=<user|system> env=<ENV_KEY>`; read the named key from the actual running service process environment, never its configuration. Probe on every close/publication. A changed named version is stale; a missing service/process, inaccessible probe, missing field/key, or unavailable value is unverifiable. Resolve typed identity before owner mapping and never fall back to cwd or Git. The authenticated receipt names the exact declaration and includes observed-version evidence; absent probe evidence is unverifiable. Changing a binding requires a reasoned relink.

## User-owned pending checks

`block` additionally accepts `awaitingUser: { action: string; ids?: string[] }`. The action must not be blank; omit this field for agent-owned blockers. It is saved as row metadata without verifying completion. `unblock` clears both the blocker note and pending user check.

For a check only the user can perform, record `todo` with `op="block", task="<exact row>", awaitingUser={"action":"Press Archive on both cards","ids":["card-a","card-b"]}`. The publication gate shows that action once, then stays quiet on agent turns until the next user message. The notice is saved on the session branch, so resuming does not repeat it. New user messages re-evaluate the current check; changed checks are announced again. Ordinary agent-owned unverified rows still block on every attempt, including when another row awaits the user.

An awaiting-user check is never evidence of completion: native and slash `todo done` stay blocked. After the user explicitly confirms the action, use `unblock` to clear the check; the row still needs a fresh authenticated audit. Alternatively, a fresh `qa-auditor` pass received after the check was recorded can satisfy it if its artifact is current. Do not infer confirmation merely from a new message or from recording `awaitingUser`.

## Read-only amendment history

Read-only views append relink amendment history from that tool instance's session manager only (requirement id, timestamp, old/new rows, and reason), without writing a ledger snapshot.
