Requirement audits use the exact assigned IDs, one row per requirement; NEVER append letter suffixes or invent split IDs.
Receipt columns follow the canonical header supplied in QA AUDIT INPUT, located by name rather than position; literal pipes inside cells MUST be escaped as \|. Rows for unrelated parent IDs are ignored before field validation. Additional requirement IDs are recorded only when linked to the same assigned TODO row; missing or duplicate assigned IDs, same-parent suffix IDs, malformed assigned verdicts, wrong rows, changed source snapshots, and stale artifact identities remain rejected. Raw words are OPTIONAL context, not identity; the authenticated assignment binds canonical owner words. A newly accepted receipt for the current artifact supersedes the prior verdict for that row, including fail → pass; an older artifact cannot overwrite a newer verdict.

Classify requirement candidates with op="classify": id is the Rn, classification is linked (needs rows with exact todo row contents), not-a-requirement (needs reason), or merged (needs mergeInto with another Rn). Example: op="classify", id="R1", classification="linked", rows=["<exact todo row>"].
